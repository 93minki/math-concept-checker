## 목표
1. 문제 본문과 보기에 그림을 넣을 수 있게 한다. 첫 범위는 **수치로 정해지는 그림**이다: 수직선, 좌표평면(점·직선·포물선), 통계 그래프(막대그래프, 히스토그램, 도수분포다각형, 상자그림, 산점도).
2. AI가 그림이 든 문제를 만들고, 코드가 그림 데이터를 검사하고, 에이전트가 그려진 그림을 보며 검토할 수 있게 한다.
3. 성취기준 3개에 그림 평가 항목을 시험으로 넣어 생성부터 풀이 화면까지 전체 흐름을 확인한다.

이번 계획에 넣지 않는 것
- 도형 그림(각의 위치, 원, 전개도, 작도). 점·선분 위치를 정하는 방식이 따로 필요해 다음 계획에서 다룬다 (결정 2).
- 학생이 직접 그리는 입력. "그리기"는 알맞은 그림을 보기에서 고르는 문제로 바꾼다 (결정 3).
- 이미 승인된 문제를 그림 문제로 바꾸는 일. 승인된 문제는 고치지 않는다 (`docs/DESIGN.md` "문제 상태").
- 남은 중3 (`9수02-21`, `9수03-18`, 시험 성취기준의 나머지 자리), Docker 배포, F-02, F-11.

### 이 작업을 하는 이유 (근거)
- 사용자 결정 (2026-11-12): 다음 계획은 "(나) 그림 지원 먼저".
- 그림이 없어 묻지 못한 내용 (`docs/PROGRESS.md` "그림 지원 필요"): 그래프 읽기(`9수02-06`), 부등식의 해를 수직선에 나타내기(`9수02-11`, `9수02-12`), 일차함수 그래프 그리기·교점 읽기(`9수02-15`, `9수02-18`), 히스토그램·도수분포다각형·막대그래프(`9수04-02~04`), 수직선 위 점 읽기(`9수01-09`), 상자그림·산점도 읽기(`9수04-08`, `9수04-09`), 이차함수 그래프 그리기(`9수02-22`), 각의 위치(`9수03-02`), 전개도(`9수03-07`). 이 가운데 도형 2개를 뺀 나머지가 첫 범위의 그림 종류로 그릴 수 있다.
- 지금 문제는 글과 KaTeX만 쓴다 (`docs/DESIGN.md` "그림 없음"). 본문에 마크다운 표가 있는 승인 문제 45개(1,095개 중, 성취기준 12개)도 표로 그려지지 않고 `|` 기호가 그대로 보인다 (`frontend/src/components/math-text.tsx`는 `$...$`만 나눠 그림, 2026-11-12 `backend/data/bank/` 집계).

## 이전 계획에서 이어받은 것
- 시험 단원(원주각·이차함수)도 글만으로 결함이 없었다. 그림 지원의 목적은 "그림이 없어 묻지 못한 내용"을 묻는 것이다. (출처: plans/2026-11-12_grade3-part1.md)
- 시험 성취기준 JSON(`9수02-22`, `9수03-19`)의 `variants`가 1이다. (출처: plans/2026-11-12_grade3-part1.md)
- 개념 데이터는 `docs/DESIGN.md` "개념 데이터 작성 규칙"을 따르고, 적재 전 `find_banned_terms`로 검사한다. 생성 전 최소 호출로 API 키를 확인한다. (출처: plans/2026-11-12_grade3-part1.md, plans/2026-11-11_grade2.md)
- 에이전트가 모든 문제의 정답·오개념 연결·범위를 확인한 뒤 승인한다. AI 검사(v7)만으로는 오개념 연결 오류를 잡지 못한다. (출처: `docs/DESIGN.md` "검증")
- 사용자·AI가 만든 글을 HTML로 바로 넣지 않는다 (`AGENTS.md` 4.3).

## 결정 사항 (사용자 결정, 2026-11-12: "추천대로 승인할게, 구현해")
결정 1~9의 추천안을 채택한다. 구현 허락은 이 계획의 단계 2~5에 적용한다 (`AGENTS.md` 3.1).

1. **그림을 만드는 방식**
   - 추천 (안 A): 문제에 **그림 데이터(JSON)** 를 둔다. 예: `{"kind": "boxplot", "series": [{"label": "A반", "min": 40, "q1": 50, ...}]}`. AI는 수치만 정하고, 우리 React 부품이 SVG로 그린다.
     - 근거: AI가 만든 글을 HTML로 넣지 않는 규칙(`AGENTS.md` 4.3)을 그대로 지킨다. 수치가 데이터로 있으니 코드가 검사할 수 있다(예: 상자그림 다섯 수치가 커지는 순서인지, 축 범위 안인지). 새 라이브러리 없이 SVG 요소만 쓴다.
   - 다른 안 B: AI가 SVG 문자열을 만든다. 모양이 자유롭지만 정확한지 코드로 검사하기 어렵고, 정화(sanitize)를 거쳐도 AI 마크업을 화면에 넣게 된다.
   - 다른 안 C: 그래프 라이브러리(JSXGraph 등)를 쓴다. 결국 그림 데이터는 안 A처럼 필요하고 의존성이 늘어난다. 근거 없음 (비교 시험 안 함).
2. **첫 범위 그림 종류**: 추천은 수직선, 좌표평면(점, 직선, 포물선, 구간 표시), 통계 그래프 5종. 모두 수치로 정해져 검사가 쉽다. 도형(각, 원, 전개도)은 다음 계획에서 다룬다.
3. **그리기 문제**: 학생이 그리는 입력은 만들지 않는다. "그래프를 그린다"는 그림 보기 5개 중 알맞은 것을 고르는 문제로 바꾼다. 그래서 **보기에도 그림**을 넣는다 (보기마다 그림 0~1개).
   - 화면: 그림 보기는 데스크톱 2열, 360px에서 1열로 쌓는다. 보기 그림은 작게(높이 상한) 그리고 가로 넘침이 없게 한다.
4. **문제당 그림 수와 위치**: 본문 그림 0~1개, 본문 글 아래에 둔다. 보기 그림은 보기마다 0~1개. 해설에는 그림을 넣지 않는다 (해설은 글로 그림을 가리킨다).
5. **본문 표 렌더링도 이번에 넣는다** (추천): 지금 45문제가 `|` 기호로 보인다. 본문의 마크다운 표(머리줄 + 구분줄 + 행)만 표로 그리고, 칸 안 글은 지금처럼 `$...$`만 KaTeX로 그린다. HTML로 해석하지 않는다. 360px에서는 표만 가로 스크롤한다. 데이터는 바꾸지 않으므로 승인 문제를 고치지 않는다.
6. **DB·데이터 형식**
   - `questions`에 `figure jsonb`(본문 그림), `question_choices`에 `figure jsonb`(보기 그림) 열을 추가한다 (null 허용, 기존 문제는 null). 승인 문제 보호 트리거는 그대로 적용된다.
   - `bank_insert_question`, `bank_import_question`, 내보내기 JSON에 그림을 넣는다. 기존 내보내기 파일은 그림이 없어도 그대로 가져올 수 있어야 한다.
   - 개발 프로젝트에 마이그레이션 적용은 사용자가 `supabase db push`로 한다 (`AGENTS.md` 3.2).
7. **AI 생성·검증 (프롬프트 v8)**
   - 생성 프롬프트에 그림 데이터 형식과 "그림을 읽어야 답이 나오는 문제는 본문 글에 같은 수치를 다시 쓰지 않는다"를 넣는다. 그림은 개념 데이터 평가 항목이 그림을 요구할 때만 넣는다.
   - 코드 검사: 그림 데이터 형식(Pydantic), 종류별 수치 규칙, 축 범위, 점·자료 개수 상한.
   - AI 검사: 그림 데이터를 JSON으로 받아 직접 풀어 본다 (그림을 눈으로 보지는 못한다. 이 한계는 에이전트 검토로 메운다).
   - 에이전트 검토: `review-html`이 화면과 **같은 그리기 부품**으로 그린 그림을 보여 준다. 에이전트는 Playwright 스크린샷으로 그림을 본다.
8. **시험 생성 (성취기준 3개, 비용 상한 $1)**: 개념 데이터에 그림 평가 항목을 추가하고 사용자 승인을 받은 뒤, 그 항목만 일반·고난이도 변형 1씩 생성한다.
   - 추천 성취기준: `9수04-08` 상자그림 읽기, `9수02-22` 이차함수 그래프 고르기(보기 그림), `9수02-12` 부등식의 해를 수직선에서 고르기(보기 그림). 세 그림 종류(통계, 좌표평면, 수직선)와 본문·보기 그림을 모두 시험한다.
   - 남은 크레딧 약 $13.6 (PROGRESS 2026-11-12, 에이전트 계산).
9. **작업 분담** (`~/.claude/rules/delegation.md`): 설계·지시서·검수는 Opus, 구현(마이그레이션, 백엔드 형식·검사·프롬프트, 프론트엔드 그리기 부품·표·보기 화면, 테스트)은 Codex pane에 맡긴다. **코드 작성은 `AGENTS.md` 3.1에 따라 사용자 허락이 필요하다.** 계획 승인 때 "구현해"를 함께 받으면 그 범위(이 계획의 단계 2~5)에만 적용한다.

3. **프론트엔드** (Codex): 그리기 부품(수직선, 좌표평면, 통계 5종), 본문 표, 그림 보기 배치, 진단 API가 그림을 내려 주기. 완료 조건: Vitest(종류별 그림, 표, 표 안 HTML이 글로 보임), Playwright 1280px·360px 가로 넘침 없음.
4. **시험 개념 데이터** (Opus, 단계 2·3과 겹쳐 진행): 성취기준 3개에 그림 평가 항목 추가. 완료 조건: **사용자 승인**.
5. **시험 생성·검토·승인**: 상한 $1. 에이전트가 그림을 보며 전수 검토. 완료 조건: 그림 문제가 진단에 나오고 풀이·채점·리포트까지 동작.
6. **검수·종료**: 5.3 검사 루프, `pnpm test:e2e:dev`, 사용자 수동 확인(데스크톱·폰에서 그림 문제와 표), 계획 종료, PR. 시험 결과로 다음 계획(그림 평가 항목을 다른 성취기준에 넓히기 / 도형 그림 / 남은 중3)을 사용자가 정한다.

## 완료 조건

- 시험 그림 문제가 진단에 나오고 채점·리포트까지 동작한다. 실제 AI 비용이 상한 안이고 기록했다.
