## 목표

AI 비교 시험에서 찾은 `gpt-6.1-terra`의 약점을 프롬프트·데이터 형식·코드 검사로 고치고, **GPT만으로 다시 시험해 개선을 숫자로 확인한다.**

| # | 약점 (근거: 이전 계획 full-1 결과) | 고치는 방법 | 확인 기준 |
|---|---|---|---|
| 1 | 서술형 채점에서 오개념 탐지 90% — A05의 M2(한쪽 변만 연산)를 3회 모두 놓침 | 채점 출력에 **오개념별 확인 결과**(있음/없음 + 답안에서 인용한 근거)를 받고, 탐지 목록은 코드가 그 결과로 만든다. 프롬프트에 "각 오개념을 하나씩 확인한다"는 절차를 넣는다 | 아래 "오개념 탐지 기준" 1~3 모두 충족, 채점 요소 판정 일치·3회 일관성 **100% 유지** |
| 2 | 리포트 문장에 이해도 숫자(0.25 등)를 그대로 씀 (`docs/SCORING.md` 5절 위반) | 리포트 프롬프트에 "숫자를 쓰지 말고 단계 이름으로" 명시 + 코드 검사로 소수·백분율·점수 표현을 잡는다 | 리포트 3세트 모두 숫자 노출 **0건** |
| 3 | 문제 생성 형식 오류 (평가 항목 ID·이해 수준 값을 바꿔서 돌려줌, GPT 1/21회) | AI 출력 형식에서 평가 항목 ID·개념 ID·이해 수준·유형·난이도를 **빼고 코드가 채운다** | 형식 오류 **0건** (구조적으로 생길 수 없음) |

### 오개념 탐지 기준 (사용자 결정, 2026-11-10)
놓침과 잘못 탐지를 나눠 본다. 잘못 탐지는 학생에게 없는 오개념을 말하게 되므로 더 나쁜 실패다.
1. **지난 약점 해결**: A05의 M2를 3회 중 **3회** 탐지
2. **잘못 탐지 0건**: 기대 오개념이 없는 답안(기존 A01·A02·A04·A06·A07·A09·A10 × 3회 = 21회)에서 오개념을 탐지하지 않음
3. **기존 탐지 유지**: A03의 M3, A08의 M6을 **6회 모두** 탐지
- 못 미치면 결과와 원인을 보고하고 사용자 판단을 받는다.
- 추가 답안 A11~A15(오개념이 들어간 답안, 아래 4단계)는 위 기준과 별도로 탐지율을 기록한다 (근거 보강용).

## 이전 계획에서 이어받은 것

- 실행 명령 `cd backend && uv run python -m app.ai.compare`, 실제 호출은 비용 추정·사용자 승인 후, `--max-cost-usd` 상한 (출처: plans/2026-11-10_ai-provider-compare.md)
- 프롬프트는 버전 폴더로 관리, 이전 버전은 지우지 않음, 기본값은 `PROMPT_VERSION` (같은 파일)
- 개념 데이터는 `docs/concepts/*.md`가 기준, JSON은 사본 — 함께 고친다 (같은 파일)
- 비교 결과 보기 페이지(`report.html`)를 만든 스크립트가 저장소에 없음 → 실행 명령의 기능으로 넣는다 (같은 파일)
- Codex 사용 한도가 빨리 준다 → 작은 작업은 Cursor에, 단계를 잘게 나눈다 (같은 파일)

## 지켜야 할 규칙

- 실제 AI 호출은 비용 추정을 보여 주고 사용자 승인 후, 상한을 걸고 실행 (`AGENTS.md` 3.2).
- 자동 테스트는 AI를 호출하지 않는다 (`AGENTS.md` 5.4).
- 프롬프트 v3는 `backend/prompts/v3/`에 새로 만들고 v1·v2는 남긴다.
- 비밀값 형태 값 커밋 금지, 커밋 전 스테이징 변경 검사 (`AGENTS.md` 4.3).
