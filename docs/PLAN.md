## 이전 계획에서 이어받은 것 (출처: `plans/2026-11-13_ui-polish.md` 인계)
- 화면 요소는 Astryx 컴포넌트로 만들고, 사용법은 `pnpm exec astryx component <Name>`으로 읽는다. 조사는 필요한 컴포넌트만, 저장소의 기존 사용 예부터 따른다.
- 테마 `concept`(stone 바탕, Pretendard, 데스크톱 16px, 컨트롤 44px). 테마를 바꾸면 `astryx theme build/add/use`를 다시 하고 생성 파일은 Prettier로 정렬하지 않는다.
- 리포트는 숫자 없이 단계만(`docs/SCORING.md` 5절). 리포트 표시 컴포넌트 `report-summary.tsx`를 랜딩 샘플이 같이 쓴다.
- 화면 검수는 스크린샷 없이 E2E와 확인 경로만(사용자 지시). `e2e-dev` 검사를 넣으면 그 자리에서 `pnpm test:e2e:dev`.
- 개발 서버를 켠 채 `pnpm build`를 돌린 뒤에는 개발 서버가 새 코드를 내보내는지 확인한다.
- 설치가 막히면 바로 사용자에게 명령을 요청한다.

## 결정 사항 (사용자 결정 2026-11-13)
1. **고칠 곳 목록:** (다) 둘 다 — 사용자 지적 목록 + 에이전트 `better-interface` 검토 초안을 합쳐 사용자가 고른다.
2. **A/B 시안:** 만든다. 화면마다 `?__variant=` 시안 두 개, 사용자가 고른다("A/B 시안 만들어줘 내가 선택할게"). 고르지 않은 시안과 장치는 지운다.
3. **구현 담당:** Cursor(`composer-2.5`) 먼저, Codex 5시간 한도가 15:16에 풀리면 Codex. Cursor도 못 쓰면 Opus가 직접 ("커서를 좀 사용하다가 시간 지나면 코덱스를 쓰도록 해. 만약 그전에 커서도 못 쓴다면 Opus 너가 해라").
