## 결정 사항 (사용자 결정 2026-11-12)
1. **현재 화면 캡처:** 개발 Supabase 시험 계정 A로 로그인해 캡처한다 (사용자 "화면 캡처는 허락할게"). 운영 프로젝트와 실제 AI는 쓰지 않는다(AI 가짜 모드). 계정 A에 진단 기록이 1~2개 늘 수 있다.
2. **한글 글꼴: Pretendard를 저장소에 넣어 쓴다** (사용자 "Pretendard를 사용할거야… 프로젝트에 넣어두는게 낫지 않나?").
   - 파일: npm 패키지 `pretendard` 1.3.9의 가변 글꼴 동적 서브셋(`dist/web/variable/woff2-dynamic-subset/` 92개, 3.0MB, 조각당 약 35KB)과 `@font-face` CSS(`pretendardvariable-dynamic-subset.css`), 라이선스 `dist/LICENSE.txt`(SIL OFL 1.1). 에이전트가 npm 레지스트리에서 받아 확인했다 (2026-11-12, tarball sha256 앞자리 `0ffc240cee83be02`).
   - 위치: `frontend/public/fonts/pretendard/` (글꼴·CSS·LICENSE). CDN은 쓰지 않는다.
   - 동적 서브셋을 고른 이유: 브라우저가 화면에 나온 글자의 조각만 받는다(`unicode-range`). 가변 글꼴 한 파일(2.0MB)은 첫 방문에 전부 받아야 한다.
3. **구현 허락과 A/B 방식** (사용자 "구현 허락하는데… 예시로 A,B 정도를 만들어서… 선택은 내가 할거야"):
   - 화면을 새로 꾸밀 때마다 에이전트가 말로 설명하거나 하나만 만들지 않는다. 서로 다른 시안 A, B를 실제로 만들어 보여 주고, 사용자가 고른다.
   - 보여 주는 방법: 1280px·360px × 라이트·다크 캡처를 나란히 보여 준다. 사용자가 직접 눌러 볼 수 있게, 개발 서버에서 주소 뒤 `?variant=a`, `?variant=b`로 바꿔 볼 수 있게 한다.
   - 고르지 않은 시안 코드는 지운다.
   - 이 계획 범위의 프론트엔드 코드(스타일·화면 컴포넌트·테스트·글꼴 파일) 작성은 허락받았다. 범위 밖 코드는 다시 묻는다.

## 단계
1. **현재 화면 캡처** (Opus)

   - 완료 조건: 사용자와 고칠 곳 목록 확인.
2. **디자인 기반 A/B** (Opus 설계, Codex 구현)
   - 서로 다른 디자인 기준 A, B(색·간격·모서리·버튼·카드·머리말)를 만든다. 예: A 차분한 학습 도구, B 친근한 학생용. 글꼴은 둘 다 Pretendard다.
   - 첫 화면에 A, B를 적용해 보여 드린다.
   - 완료 조건: 사용자가 A/B 중 고름.
3. **디자인 기반 적용** (Codex 구현, Opus 검수)
   - 고른 기준을 CSS 변수(라이트·다크)와 공통 요소(머리말, 버튼, 카드, 입력창, 안내 문구)로 만들고 모든 화면에 적용한다.
   - 완료 조건: 5.2 검사 통과, 모든 화면 1280·360 × 라이트·다크 캡처 확인, 360px 가로 넘침 없음.
4. **화면별 사용성 A/B** (Codex 구현, Opus 검수) — 화면마다 A, B 시안을 만들어 보여 드리고 고르신 것만 남긴다. 순서와 범위는 단계 1 목록에서 확정한다.
   - 첫 화면: 학년별 묶음, "일부만" 안내가 붙은 단원 카드
   - 풀이: 단계·진행 표시, 남은 문제 수, 저장 상태
   - 리포트: 개념별 이해도 막대와 단계 색, 오개념·학습 방향 구역 구분
     - 리포트 화면을 고른 뒤, 그 컴포넌트에 샘플 데이터(`9수02-03`)를 넣어 랜딩(`/login`)에 "샘플 리포트" 구역을 추가한다. 실제 화면과 같은 모양을 유지하려고 리포트 완성 뒤로 미룸 (사용자 결정 2026-11-12 "오케이 그렇게하자").
   - 지난 기록: 카드에 단원, 시작 시각, 상태 배지, 완료 진단의 이해도 요약을 함께 보여 같은 시각·단원도 구별되게. 이해도 요약을 목록 API가 이미 주는지 확인하고, 없으면 API 변경이 필요하니 다시 묻는다.
   - 로그인·가입
   - 완료 조건: 화면마다 사용자가 A/B를 고름, 5.2 검사 통과, 고른 화면의 Vitest·Playwright 테스트.
5. **검수·종료** (Opus)
   - 5.2 전체 검사, `pnpm test:e2e:dev`, 사용자 수동 확인(데스크톱·폰), 문서 정리(`DESIGN.md`에 디자인 기준), 계획 종료, PR
