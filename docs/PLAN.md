## 이전 계획에서 이어받은 것
- 승인된 문제는 바꾸지 않는다. 수정 = 같은 자리에 새 문제 승인 + 기존 문제 사용 중지(DB 트리거). (출처: `DESIGN.md` "문제 은행", plans/2026-11-13_ui-polish-2.md 문제 221caf87 교체)
- 직접 쓴 문제는 검사를 거치게 하는 기능을 먼저 만든다 — `app.bank import`는 검사가 없어 직접 쓴 문제에 쓰지 않는다. (출처: `PROGRESS.md` 문제 은행 생성 방식, 사용자 결정 2026-11-11·12)
- 화면은 `DESIGN.md` "화면 스타일 기준"(사이드바 메뉴 추가, 본문 폭 고정, 토큰 색, 그림자 2px 이하). 문제 판(`.problem-sheet`)은 Astryx 밖. (출처: plans/2026-11-14_landing.md 인계)
- 시험 계정 A·B는 절대 바꾸지 않는다. `test:e2e:dev`는 3100·8100 임시 복사본. (출처: plans/2026-11-14_account.md 인계)
- 실제 AI 호출은 비용 추정과 사용자 승인 뒤. 남은 크레딧 약 $5.2 (출처: `PROGRESS.md` 2026-11-12, 에이전트 계산).

## 단계
1. **설계** — `DESIGN.md`에: 신고 테이블(사용자·문항·진단 문항 자리·유형·설명·상태·처리 메모·시각, 같은 사용자·문항의 처리 전 중복 막기), RLS(본인 신고만 읽기·쓰기, 상태는 서버만 변경), 관리자(결정 1), API(학생: 신고·내 신고 목록 / 관리자: 문항별 목록·상세·AI 수정안·직접 수정 검사·승인·문제 없음), 수정 승인 흐름(기존 생성·검사 코드 재사용, 직접 수정은 코드 검사 + AI 검사), 화면. 완료 조건: 사용자 확인.
2. **DB** — 마이그레이션 작성, 개발 프로젝트 적용은 사용자 확인 후(`AGENTS.md` 3.2). 완료 조건: RLS로 다른 사용자 신고를 읽거나 쓸 수 없음(e2e-dev 접근 검사에 추가, 시험 계정 A·B는 신고만 하고 계정은 바꾸지 않음 — 시험 신고는 테스트 끝에 정리).
3. **백엔드 API** — 테스트 먼저(외부 호출 모두 가짜): 비로그인 401, 남의 신고 접근 불가, 관리자 아니면 403, 중복 신고 409, 수정 승인 시 새 문제 승인 + 기존 사용 중지 + 신고 상태 "수정함". 완료 조건: 5.2 백엔드 검사.
4. **학생 화면** — 풀이·리포트 문제마다 "오류 신고"(대화 상자), 사이드바·폰 머리말 "내 신고"(학습하기 / 지난 기록 / 내 신고 / 내 정보), `/reports`. 완료 조건: 5.2 프론트 검사, 360px, 정답 비노출 테스트.
5. **관리자 화면** — `/admin/reports` 목록·상세(학생 화면과 같은 문제 판 + 정답·해설·채점 기준 + 신고들), AI 수정안·직접 수정(검사 결과 표시)·승인·문제 없음. 관리자가 아니면 들어갈 수 없음. 완료 조건: 5.2 검사, 실제 AI 시험은 결정 2에 따름.
6. **검수·종료** — 5.2 전체, `pnpm test:e2e:dev`, 사용자 확인(학생 신고 → 관리자 처리 → 내 신고 상태), 계획 종료, PR.
