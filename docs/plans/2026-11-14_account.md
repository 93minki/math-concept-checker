## 지켜야 할 것 (사용자 지시 2026-11-14)
- **시험 계정 A·B(`E2E_USER_A_*`, `E2E_USER_B_*`)는 절대 지우거나 바꾸지 않는다.** 탈퇴·비밀번호 변경 테스트는 모두 가짜(백엔드 `dependency_overrides`, 관리자·카카오 호출 가짜, 프론트 가짜 API)로 한다. 실제 탈퇴·비밀번호 변경은 사용자가 별도 계정으로 직접 확인한다. 위임 지시서에도 적는다.

## 확인한 사실
- `profiles`와 `diagnoses`는 `auth.users`를 `on delete cascade`로 참조하고, `diagnosis_items`·답안·`gradings`·`reports`도 진단을 따라 cascade로 지워진다 (`supabase/migrations/20261110023848_create_profiles.sql:9`, `20261110220000_create_diagnoses.sql:9,36,51`, `20261111000000_create_gradings_reports.sql:17,35`). 따라서 Supabase Auth 사용자를 지우면 이 앱의 사용자 데이터는 모두 지워진다.
- 사용자 삭제는 Supabase Auth 관리자 API로만 할 수 있고 Secret key가 필요하므로 백엔드에서 한다 (`AGENTS.md` 4.3: Secret key는 서버에서만).
- 이메일 인증은 **이메일 가입 때만** 한다: 가입 요청에 `emailRedirectTo`를 주고 "확인 메일을 보냈어요"를 보인다 (`frontend/src/app/signup/page.tsx:31,39`). 카카오 가입은 Supabase 확인 메일이 없다(카카오가 이메일을 넘겨줌). 카카오 가입자는 비밀번호가 없으므로 비밀번호 변경은 이메일 가입자에게만 보인다.

## 정한 것 (사용자 2026-11-14)
- `/account`에 보일 정보: 가입 방식(이메일·카카오), 이메일, 가입일, 약관 다시 보기, 비밀번호 변경(이메일 가입자만), 회원 탈퇴. ("나머지는 저 정도면 충분할 듯")
  - 약관 다시 보기를 두는 근거: 가입 때 동의한 내용(받는 정보, 탈퇴 시 삭제, OpenAI로 보냄)을 가입 뒤에도 확인할 곳이 지금은 없다. 개인정보 보호법 제30조(개인정보 처리방침의 수립 및 공개)가 처리방침을 정보주체가 쉽게 확인할 수 있게 공개하도록 한다. 정식 처리방침은 `PROGRESS.md` 공개 전 필수 항목이고, 이번에는 가입 때 보인 동의 문구(`frontend/src/app/privacy-consent.tsx`)를 그대로 다시 보여 준다.
- 탈퇴 확인: 대화 상자에 경고만 — "정말 탈퇴하시겠어요? 탈퇴하면 진단 기록이 모두 사라지고 되돌릴 수 없어요." + 취소·탈퇴 버튼. 입력 확인은 하지 않는다("저거는 그냥 과하고").
- 비밀번호 변경: Supabase 재인증(이메일 확인 코드)은 쓰지 않는다. 두 단계 — (1) 현재 비밀번호 입력 → "확인" 버튼으로 맞는지 확인(Supabase 이메일·비밀번호 로그인 호출로 확인) (2) 맞으면 새 비밀번호·새 비밀번호 확인 입력과 "변경" 버튼이 켜진다 → Supabase 사용자 비밀번호 갱신. 입력할 때마다 확인하지 않고 버튼을 눌렀을 때만 확인한다(글자마다 서버로 비밀번호를 보내면 요청이 많아지고 추측 시도처럼 보인다). 틀리면 "현재 비밀번호가 맞지 않아요". 위 방식이 공식 API로 되는지(갱신 API가 현재 비밀번호를 따로 요구하는 설정이 켜져 있는지 등)는 단계 2에서 Supabase 공식 문서로 확인한다.
- 카카오 연결 끊기를 이번에 한다. 방법(카카오 "연결 끊기" API, 앱 어드민 키를 쓰는 서버 호출인지 사용자 토큰 호출인지)과 필요한 새 비밀값은 단계 2에서 카카오 공식 문서로 확인한다. 새 비밀값이 필요하면 `.env.sample`에 키 이름만 넣고 값은 사용자가 넣는다(`AGENTS.md` 4.3).
- 탈퇴·비밀번호 변경 E2E는 가짜로만 (위 "지켜야 할 것").

2. **조사·설계** — 공식 문서 확인: Supabase 비밀번호 변경(재인증), Supabase 관리자 사용자 삭제, 카카오 연결 끊기. `DESIGN.md`에 `/account` 화면, 비밀번호 변경 흐름, `DELETE /account`(로그인 필요, 자기 계정만, 카카오 가입자는 카카오 연결 끊기 → Auth 사용자 삭제 순서, 한쪽 실패 시 처리, 성공 뒤 프론트 로그아웃·`/`로). 완료 조건: 사용자 확인.
3. **백엔드 `DELETE /account`** — 테스트 먼저: 로그인 없으면 401, 다른 사용자 ID를 지정할 수 없음(요청에 사용자 ID를 받지 않음), 카카오 가입자만 연결 끊기 호출, 관리자·카카오 호출 실패 시 정해진 오류, 성공 시 관리자 삭제를 토큰의 `sub`로 한 번. 모든 외부 호출은 가짜. 완료 조건: 5.2 백엔드 검사 통과.
4. **프론트 `/account`** — 정보 표시, 약관 다시 보기, 비밀번호 변경(이메일 가입자만, 두 단계, 폼 `method="post"`·스크립트 전 제출 막기, 비밀번호를 주소·로그에 넣지 않음), 탈퇴 경고 대화 상자, 사이드바·폰 머리말 "내 정보". 완료 조건: 5.2 프론트 검사, 360px 넘침 없음.
5. **검수·종료** — 5.2 전체, `pnpm test:e2e:dev`, 사용자 수동 확인(실제 탈퇴 1회는 사용자가 개발 프로젝트의 별도 계정으로), 계획 종료, PR.
