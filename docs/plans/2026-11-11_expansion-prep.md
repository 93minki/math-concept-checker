## 목표
나머지 성취기준 59개로 문제 은행을 넓히기 **전에**, 넓힐수록 비용이 커지는 문제 네 가지를 먼저 고친다.
1. **용어 검증**: 단원이 늘어도 "아직 배우지 않은 용어"를 성취기준마다 손으로 적지 않게 한다. 교육과정 용어표 하나에서 자동으로 만든다 (F-05 "교육과정 범위 이탈을 걸러 낸다").
2. **프롬프트 v6**: 생성 단계의 "필수:" 표시와 리포트 첫 문장을 고친다. 새 문제를 대량으로 만들기 전에 넣어야 효과가 있다.
3. **문제 은행 내보내기·가져오기**: 지금 승인 문제는 개발 DB에만 있다. 백업과 운영 프로젝트 이전 수단을 만든다.
4. **출제 조회 줄이기**: 진단 API가 요청마다 문제 은행 전체(본문 포함)를 읽는다. 문제가 약 60배로 늘기 전에 줄인다.

이번 계획에 넣지 않는 것
- 실제 개념 데이터 작성과 문제 생성 (다음 계획 "중1 3단원 완성")

## 이전 계획에서 이어받은 것
- 용어 검증이 문서와 코드가 다르다. 문서는 "용어 목록 밖의 수학 용어 없음"(허용 목록), 코드는 개념 데이터의 `not_yet_learned`만 막는다 (`backend/app/ai/validators.py`). 결정 대기. (출처: plans/2026-11-10_question-bank.md 인계, `docs/DESIGN.md` "검증")
- `9수02-03`의 `not_yet_learned`는 에이전트가 손으로 골랐다. 기준은 "중1 3단원 이후 단원의 성취기준에 속하는 용어, 같은 학년 뒤 단원 포함"이다 (`backend/data/concepts/9수02-03.json` `_not_yet_learned_basis`).
- 리포트 검증도 `not_yet_learned`를 JSON에서 읽는다 (`docs/DESIGN.md` "채점·2단계·리포트" AI 연결).
- "필수:" 표시
  - 승인 문제 채점 요소 14개 중 10개가 "필수:"로 시작한다.
  - 승인 문제는 고치지 않으므로 학생 응답에서만 뗀다 (`student_description`).
  - 생성 프롬프트에서 막는 일이 남았다. (출처: plans/2026-11-10_grading-report.md 인계)
- 리포트 첫 문장이 단계 이름("~ 단계예요")을 나열하는 느낌이다 (2026-11-10 실제 AI 확인, `docs/PROGRESS.md`).
- 실제 AI 호출은 매번 비용 추정을 보여 주고 승인받은 뒤 한다. 기본 프롬프트는 v5다 (`backend/app/ai/prompts.py` `PROMPT_VERSION`). (출처: plans/2026-11-10_question-bank.md 인계)
- 마이그레이션은 버리는 Postgres 17 컨테이너에 역할(anon, authenticated, service_role)을 만들고 먼저 시험한다. 원격 적용은 사용자가 `supabase db push`로 직접 한다. (출처: 같은 인계, 사용자 지시 2026-11-11)
- 승인 문제는 고칠 수 없고(트리거), 문제 저장은 함수 `bank_insert_question`이 한다 (`docs/DESIGN.md` "DB 스키마" 문제 은행).
- 위임 (출처: plans/2026-11-11_history.md 인계)
  - Codex·Cursor는 Herdr pane(`w9:pQ`, `w9:pR`)에서 실행한다.
  - Codex 샌드박스는 포트·네트워크를 못 쓴다.
  - Cursor는 명령마다 실행 승인을 기다린다.
  - 지시서 끝에 "마지막에 `pnpm format`"을 적는다.

## 결정 사항 (사용자 결정, 2026-11-11: "추천대로 진행해")
아래 1~4의 **추천안**(1 안 A, 2 실제 AI 작은 시험, 3 안 A, 4)을 채택한다. 1단계에서 `docs/DESIGN.md`로 옮긴다.

1. **용어 검증 방식**
   - 안 A (추천): **교육과정 용어표 하나에서 금지 목록을 자동으로 만든다.**
     - 새 데이터 `backend/data/curriculum/terms.json`
       - 교육과정 원문 각 영역의 "용어와 기호"(초등·중학·고등)를 옮긴다.
       - 중학교 용어마다 처음 다루는 성취기준을 붙인다.
       - 원문 근거: 각 영역의 "용어와 기호로 ~를 다룬다" 문장 (교육과정 PDF).
       - 용어 → 성취기준 연결은 원문에 없다. 에이전트가 추론하고 사용자 승인을 받는다 (`9수02-03`을 만들 때와 같은 방식).
     - 어떤 단원의 금지 목록 = 고등학교 용어 전부 + 그 단원보다 뒤 단원(학년, 번호 순, 같은 학년 뒤 단원 포함)의 성취기준에 연결된 중학교 용어.
       - 초등 용어와 앞 단원 용어는 허용한다.
     - 문제 생성·검사 프롬프트, 코드 검사, 리포트 검증이 모두 이 목록을 쓴다. 개념 JSON의 `not_yet_learned`는 없애고 코드가 만든다.
     - `docs/DESIGN.md` "검증"의 "용어 목록 밖의 수학 용어 없음"을 위 규칙으로 고친다.
     - 한계: 어느 목록에도 없는 수학 용어(교육과정 밖 용어)는 코드가 알아볼 수 없다. 지금처럼 AI 검사가 맡는다.
   - 안 B: 허용 목록 검사.
     - 문장에서 "수학 용어"를 골라내야 하는데, 목록에 없는 단어가 수학 용어인지 코드가 판단할 방법이 없다.
     - 결정적으로 구현할 수 없어 추천하지 않는다. 근거 없음 (한국어 수학 용어 분석기를 찾지 못함).
   - 안 C: 지금처럼 성취기준마다 손으로 적는다. 59번 반복되고, 사람마다 기준이 달라진다.
2. **프롬프트 v6 범위와 확인 방법**
   - 생성
     - 채점 요소 설명에 "필수:" 같은 표시를 붙이지 않게 한다. 필수 여부는 `required` 값으로만 낸다.
     - 코드 검사에도 "채점 요소 설명이 필수 표시로 시작하면 실패"를 추가한다.
   - 리포트: 첫 문장이 단계 이름을 나열하지 않고 학생에게 말하듯 시작하게 한다.
   - 나머지 프롬프트(검사·채점)는 v5와 같게 둔다.
   - 확인 (추천): 실제 AI로 작게 시험한다.
     - 비교 시험 실행 명령으로 `9수02-03` 문제 몇 개(서술형 포함)를 생성하고 리포트 3세트를 만들어 본다. 문제 은행 DB에는 넣지 않는다.
     - 비용은 실행 전 추정해 승인받는다. 참고로 v4 재시험 전체가 $0.512였다 (plans/2026-11-10_prompt-v3.md 인계).
     - 판정 기준
       - 생성 문제의 채점 요소 중 "필수" 표시로 시작하는 것 0개
       - 리포트 3세트의 첫 문장에 단계 이름 나열 0건 (에이전트 판정, 사용자 확인)
       - 형식 오류 0건
   - 이미 승인된 문제는 그대로 둔다 (승인 문제는 고치지 않는다).
3. **문제 은행 내보내기·가져오기**
   - 명령: `bank export --standard <코드> | --all --out <파일>`, `bank import <파일>`
     - 담는 것: 문제·보기·채점 요소·오개념 연결·상태·승인 정보·검증 기록·생성 정보, 백로그
     - 가져오기는 ID를 그대로 쓴다. 이미 같은 ID가 있으면 내용이 같을 때만 건너뛰고, 다르면 실패한다. 여러 번 실행해도 결과가 같다.
     - 승인된 문제를 승인 상태 그대로 넣어야 한다. 지금 `bank_insert_question`이 이를 받는지 1단계에서 확인한다. 안 되면 새 마이그레이션으로 함수를 고친다 (원격 적용은 사용자).
     - 시험은 로컬 Postgres 17 컨테이너로만 한다. 원격에는 가져오기를 실행하지 않는다.
   - 내보낸 파일을 어디에 둘지
     - 안 A (추천): 저장소 `backend/data/bank/<성취기준>.json`에 커밋한다.
       - git이 백업이 되고, 운영 이전의 원본이 된다.
       - 승인한 문제가 바뀌지 않았는지 diff로 볼 수 있다.
       - 저장소가 공개라(`gh repo view` 확인, 2026-11-11) 내보내기 파일의 승인자 값(`--approver`로 입력한 이름)도 공개된다. 사용자 결정 (2026-11-11): 공개되어도 괜찮다. 승인자 값은 원본 그대로 내보낸다.
     - 안 B: git 제외 폴더(`experiments/`)에 두고 사용자가 따로 백업한다.
4. **출제 조회 줄이기**
   - 출제와 단원 상태 계산에는 문제 ID, 평가 항목, 난이도, 변형, 상태만 읽는다.
   - 본문·해설·모범 답안은 진단에 나간 문제 ID로만 읽는다.
   - 응답과 동작은 바꾸지 않는다. 기존 pytest가 그대로 통과해야 하고, "본문을 전체 조회하지 않는다"는 테스트를 추가한다.
