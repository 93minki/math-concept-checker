- AI를 쓰는 세 곳(문제 은행 생성, 서술형 채점, 리포트 문장)에 쓸 **제공사와 모델을 시험 결과로 정한다.** 후보: Google Gemini, OpenAI GPT. Claude는 자리만 두고 시험하지 않는다 (사용자 결정, 2026-11-10).

## 지켜야 할 규칙 (이번 계획에서 특히)
- **실제 AI API 호출은 비용이 드는 외부 호출이다.** 실행 전에 예상 비용을 계산해 보여 주고 사용자 승인을 받는다 (`AGENTS.md` 3.2). 승인 범위를 넘는 재실행도 다시 승인받는다.
- 자동 테스트(`pytest` 등)는 AI를 호출하지 않는다. 제공사 연결은 가짜로 바꿔 테스트한다 (`AGENTS.md` 5.4). 실제 호출은 별도 시험 명령으로만 한다.
- API 키는 `backend/.env`에서 프로그램이 읽기만 한다. 키를 출력·기록하지 않는다.
- 시험 원본 결과(AI 응답 전체)는 `experiments/ai-provider-compare/`(git 제외)에 둔다. 결정에 필요한 측정값만 `DESIGN.md`에 옮긴다 (수식 렌더링 시험과 같은 방식).
- 모델 이름·가격·기능은 **시험 시점의 공식 문서**로 확인한다. 기억으로 쓰지 않는다 (`AGENTS.md` 3.3).

## 시험 설계

### 무엇을 비교하나
| 용도 | 시험 내용 | 측정 |
|---|---|---|
| 문제 생성 (F-05) | `9수02-03` 평가 항목 6개 × 난이도 2 = **12문제**를 제공사마다 생성 | ① 코드 검사 통과율 (`DESIGN.md` "검증" 1번) ② 재생성 횟수 ③ AI 검사(별도 호출)의 지적 ④ Claude 검토: 수학 오류·정답 유일성·의도한 이해 수준을 재는지 (근거 수준: 에이전트 검토, 전문가 검토 아님) |
| 서술형 채점 (F-07) | 서술형 문항 1개에 대해 미리 만든 **예시 답안 10개**를 채점, **같은 답안을 3번씩** | ① 미리 정한 기대 판정과의 일치율 (채점 요소별 충족/미충족) ② 3번 채점의 일관성 (같은 판정 비율) ③ 판단 근거가 채점 요소를 실제로 가리키는지 |
| 리포트 문장 (F-08) | 고정된 채점 결과 3세트(이해 부족·기본·깊이)로 리포트 문장 생성 | ① 넘겨준 숫자·단계·오개념을 바꾸지 않았는지 (코드 검사) ② 교육과정 밖 용어 사용 여부 ③ 쉬운 말인지 (Claude 검토) |
| 공통 | 위 전부 | 응답 시간, 토큰 사용량 → 1회당 비용, 구조화 출력(JSON 스키마) 실패율 |

### 판정 방식
- 통과율·일치율·일관성은 숫자로 비교한다. 비용은 1문제·1채점·1리포트당 달러로 적는다.
- 용도마다 다른 제공사를 고를 수도 있다 (예: 생성은 A, 채점은 B). 최종 선택은 사용자가 결과표를 보고 정한다.

## 단계
| # | 단계 | 담당 | 완료 조건 |
|---|---|---|---|
| 1 | **조사**: 공식 문서로 후보 모델(제공사별 1~2개), 가격, 구조화 출력(JSON 스키마) 지원, Python SDK 사용법 확인 → 후보 모델을 사용자에게 확인 | Claude | 근거 링크가 붙은 후보 표, 사용자 확인 |
| 2 | **데이터 형식**: 문제·보기·채점 요소·채점 결과·리포트 입력/출력을 pydantic 모델로 정의 (`DESIGN.md` "문제 데이터와 검증", `SCORING.md` 기준) | Codex | 타입 체크·단위 테스트 통과 |
| 3 | **제공사 연결**: 공통 인터페이스(문제 생성, AI 검사, 채점, 리포트) + Gemini·OpenAI 구현 + Anthropic 자리. 응답 시간·토큰 사용량 기록 | Codex | 가짜 제공사로 단위 테스트 통과, 실제 호출 없음 |
| 4 | **코드 검증기**: 보기 5개·정답 1개, 금지 표기, 교육과정 용어, 승인된 오개념 ID, 수식(KaTeX) 렌더링 검사 | Codex | 단위 테스트 (통과·실패 예시 모두) |
| 5 | **프롬프트 v1**: 문제 생성, AI 검사, 서술형 채점, 리포트. 개념 데이터·용어 목록·오개념을 넣는다. 파일로 관리하고 버전을 붙인다 | Claude 초안 → 사용자 확인 | 프롬프트 파일, 사용자 확인 |
| 6 | **채점 시험 재료**: 서술형 문항 1개, 채점 요소, 예시 답안 10개(완전·부분·오개념·무관 등)와 기대 판정 | Claude 초안 → 사용자 승인 | 사용자 승인 (출처 없음 → 전문가 검토 필요로 표시) |
| 7 | **시험 실행 명령** (`backend`의 별도 명령, pytest 아님): 위 시험을 돌리고 결과를 `experiments/ai-provider-compare/`에 저장 | Codex | 가짜 제공사로 끝까지 돌아감 |
| 8 | **비용 추정 → 사용자 승인 → 실제 실행** | Claude | 승인한 예산 안에서 실행 완료 |
| 9 | **결과 정리**: 비교표와 Claude 검토 의견 → 사용자 결정 → `DESIGN.md`·`AGENTS.md` 4.2 기록 | Claude, 사용자 | 결정과 근거 기록 |

- 검사 9개(`AGENTS.md` 5.2)는 2~7단계마다 실행한다.
- 새 Python 패키지: 각 제공사 공식 SDK (1단계에서 이름·버전 확인). 프론트엔드 패키지 추가는 KaTeX 검사에 필요할 때만 (4단계에서 방법 결정).
