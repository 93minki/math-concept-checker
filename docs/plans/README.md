# plans

끝난 작업 계획 보관함이다. 에이전트는 평소에 이 폴더를 읽지 않는다.
다음 경우에만 읽는다.
- 사용자가 요청할 때
- 새 `docs/PLAN.md`를 작성할 때 (아래 "새 계획 작성 절차")

---

## 계획 종료 절차

작업이 끝나거나 중단되면 다음 순서로 처리한다.

1. `docs/PLAN.md`의 **인계** 절을 채운다. (양식은 아래 "PLAN.md 양식")
2. 작업 중 확정된 설계를 `docs/DESIGN.md`로 옮긴다. 보관된 계획에만 남는 설계가 없어야 한다.
3. `docs/PLAN.md`를 `docs/plans/YYYY-MM-DD_주제.md`로 옮긴다.
   - 날짜는 계획을 끝낸 날이다.
   - 주제는 짧은 한글 또는 영문이며 띄어쓰기 대신 `-`를 쓴다. (예: `2026-11-09_인증-DB`)
   - 같은 이름이 이미 있으면 주제를 더 구체적으로 쓴다. 기존 파일을 덮어쓰지 않는다.
4. 아래 "계획 목록" 표 맨 위에 한 줄을 추가한다.
5. `docs/PLAN.md`를 새로 만들고 "진행 중인 작업 계획 없음."이라고 적는다.
6. `docs/PROGRESS.md`를 갱신한다.
7. 1~6의 문서 변경을 계획 브랜치에 커밋하고, `main`으로 가는 PR을 만든다 (`AGENTS.md` 3.8). 사용자 확인 후 머지하고 브랜치를 정리한다.

---

## 새 계획 작성 절차

이전 계획의 내용을 놓치지 않기 위해 다음 순서로 읽고 쓴다.

1. `AGENTS.md` 2.2의 공통 문서(`PROGRESS.md`, `DESIGN.md`)를 읽는다.
2. 이 파일의 "계획 목록"을 읽는다.
3. 가장 최근 계획 파일의 **인계** 절을 읽는다.
4. 목록에서 이번 작업과 같은 `F-xx`를 다룬 계획을 찾아 그 **인계** 절을 읽는다. 본문은 인계 절만으로 부족할 때만 읽는다.
5. 새 `docs/PLAN.md` 초안을 아래 양식으로 쓴다. 이전 계획에서 가져온 내용은 **이전 계획에서 이어받은 것** 절에 출처(파일 이름)와 함께 적는다.
6. 초안을 사용자에게 보여 주고 **승인을 받는다.** 승인 후 GitHub 이슈 `[PLAN] 주제`(라벨·마일스톤 포함)를 만들고, `main`을 최신으로 받은 뒤 그 이슈에서 계획 브랜치 `plan/YYYY-MM-DD_주제`를 만들어 `PLAN.md`를 첫 커밋으로 올린다 (`AGENTS.md` 3.8).
7. 이전 계획의 내용이 `docs/DESIGN.md`와 다르면 어느 쪽을 따를지 사용자에게 묻는다.

---

## PLAN.md 양식

```markdown
# PLAN: <주제>

- 시작일: YYYY-MM-DD
- 대상 기능: F-xx, F-yy
- 상태: 진행 중 | 완료 | 중단
- 이슈: #번호
- 브랜치: plan/YYYY-MM-DD_주제
- PR: (계획을 끝낼 때 링크)

## 목표
<이 계획으로 무엇을 끝내는가>

## 이전 계획에서 이어받은 것
- <내용> (출처: plans/YYYY-MM-DD_주제.md)
- 없으면 "없음"

## 단계
1. <단계> — 완료 조건: <확인 방법>
2. ...

## 완료 조건
- <AGENTS.md 3.7 완료 기준 + 대상 F-xx 완료 조건 중 이번 계획에 해당하는 것>

## 진행 메모
- YYYY-MM-DD: <결정, 바뀐 점, 막힌 점>

## 인계 (계획을 끝낼 때 작성)
- 결과: 완료 | 중단 (중단이면 이유)
- 끝내지 못한 일:
- 다음 계획이 알아야 할 것:
- `DESIGN.md`로 옮긴 결정:
```
